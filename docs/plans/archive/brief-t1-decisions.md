## Decisions settled for this brief (orchestrator, 2026-09-27)

1. **Names.** The new per-pick type is `remove::Decision`; inside `remove.rs` refer to the recycle one as `recycle::Decision` (drop it from the `use`). Keep `Plan { Run(Action), Skip(String) }`: it is what a `Decision` carries, so today's skip reasons (`not confirmed`, `permanent delete declined; <reason>`) and `Outcome::Skipped(reason)` stay as they are.
2. **`Decision`** (pub, in `remove.rs`): `{ candidate: &'a Candidate, plan: Plan, branch: BranchChoice }`, with `pub enum BranchChoice { NotOffered, Delete(BranchOffer), Keep(BranchOffer) }`. `Keep` exists so the `branch X kept` note still appears exactly as today when the user declines.
3. **Pure planning.** `pub fn plan_action(candidate: &Candidate, capacity: Option<BinCapacity>) -> PlanNeed` with `pub enum PlanNeed { Run(Action), AskPermanent(String) }`: link and prunable short-circuit as today, a folder goes through `recycle::recycle_decision` with size `unwrap_or(u64::MAX)`. The capacity is read at the edge by a new `pub fn read_capacity(path: &Path) -> Option<BinCapacity>` in `remove.rs` that holds today's `warn!` (move the :321-327 code there). `plan` is deleted. `agent.rs` keeps its own copy (out of scope).
4. **Review is an incremental state machine**, not a static list, because a declined loss skips that pick's later questions. New `src/tui/review.rs` (pure), declared by a new `src/tui/mod.rs` holding only `pub mod review;` and `pub mod tui;` in `lib.rs` (after `signals`). API:
   - `Review::new(candidates: &[&'a Candidate], root: &Path, capacity: &mut dyn FnMut(&Path) -> Option<BinCapacity>) -> Review<'a>`. `capacity` is called only for picks whose `plan_action` would need it (folders), once each, at construction.
   - `fn step(&self) -> Option<&Step>`: the current question, `None` when every per-pick question is answered.
   - `fn answer(&mut self, yes: bool)`: records it and moves to the next question, skipping those the answer made moot.
   - `fn totals(&self) -> Option<Totals>` and `fn decisions(self) -> Option<Vec<Decision<'a>>>`: `None` until `step()` is `None`, so an unfinished review can never be removed with defaults filled in.
   - `Step { pick: usize /* index into candidates */, kind: StepKind, body: String, question: &'static str, default: bool }`, `StepKind { Loss, Link, Permanent, Branch }`.
   - Per pick, in candidate order: **Loss** or **Link** when the pick loses something (default no; no → `Plan::Skip("not confirmed")`, no further questions for it); then **Permanent** when `plan_action` is `AskPermanent(reason)` (default no; no → `Plan::Skip("permanent delete declined; <reason>")`, no branch question); then **Branch** when `branch_offer` is `Some` for a registered pick (default yes; yes → `BranchChoice::Delete`, no → `Keep`).
   - Bodies and questions: Loss/Link body is the loss text from decision 5; Permanent body is today's :333 context text with the question `Delete it permanently?`; Branch body and question are `BranchOffer::context` / `question` as today.
   - `Totals { recycle: usize, recycle_bytes: u64, permanent: usize, permanent_bytes: u64, links: usize, prunes: usize, branches: usize, skipped: usize }` and `pub fn final_sentence(&Totals) -> String` producing, for the non-zero parts only, `Remove N items: R to the Recycle Bin (X), P permanently (Y), L links, U registrations pruned; B branches deleted. S skipped.` N = recycle + permanent + links + prunes (skipped not counted). Sizes use `report::human_bytes`; an unknown size counts 0 bytes. Omit a zero part and its separator; `N items` → `1 item` when N is 1; `B branches deleted` → `1 branch deleted`.
5. **Loss text split.** New `pub fn loss_text(candidate: &Candidate) -> Option<Loss>` in `pick.rs` with `pub struct Loss { pub kind: LossKind /* Loss | Link */, pub text: String, pub question: &'static str }`; its text is the loss with no path prefix and a capital first letter (`Remove the link only; X:\dev\yaat is not touched.`). `loss_sentence(candidate, root)` stays as the prefixed wrapper and its output is **byte-for-byte unchanged** (agent.rs and its tests are not touched). Update `loss_question_is_short_and_pathless` to assert on `loss_text` (text has no path of the pick, question ≤ today's cap) and keep the existing `loss_sentence_*` tests passing unchanged.
6. **`remove_picks`** becomes `pub fn remove_picks<'a>(decisions: &[Decision<'a>], root: &Path, on_progress: &mut dyn FnMut(Progress), offer_unlock: &mut dyn FnMut(&[PathBuf]) -> Result<UnlockOutcome>) -> Result<Vec<Swept<'a>>>`, with `pub enum Progress { Started(usize), Done(usize) }` indexed into `decisions` (a retried pick emits `Started`/`Done` again). `Plan::Skip` decisions produce `Outcome::Skipped(reason)` without touching the disk. `LiveSweeper` stores the `offer_unlock` closure and the per-item `BranchChoice` in place of the prompter. `after_removed(candidate: &Candidate, branch: &BranchChoice) -> Vec<String>`: prunes as today, then `Delete` deletes (notes as today), `Keep(offer)` adds `branch <b> kept`, `NotOffered` adds nothing.
7. **Deleted:** `trait Prompter`, `TermPrompter`, `pick::Pick`, `remove::plan`, the loss loop in `pick::pick`. `pick::pick(report, now) -> Result<Vec<&Candidate>>` keeps the MultiSelect and the `Picked <path>` echo and returns the ticked candidates (empty on Esc).
8. **`main.rs` temporary Review driver** (`sweep_interactively`): ComApartment; `pick::pick`; empty → `Nothing picked; nothing removed.` as today; `Review::new(&picked, &report.root, &mut remove::read_capacity-closure)`; loop `while let Some(step) = review.step()`: write `step.body` to stderr through `dialoguer::console::Term::stderr().write_line` (clippy denies `eprintln`), then `Confirm::new().with_prompt(step.question).default(step.default).interact()`, `review.answer(..)`. Then the final confirmation: body `final_sentence(&totals)`, question `Remove them?`, default **no**; no → print `Nothing removed.` and return. Yes → `remove_picks(&decisions, root, &mut |_| {}, &mut |paths| unlock::offer(paths))`, then the summary lines as today. When every pick was skipped (N = 0), skip the final confirmation and go straight to `remove_picks` so the skipped lines print. Keep `main.rs` small: if this makes a function exceed the lint limits, split it.
9. Module docs: rewrite `remove.rs:1-2`, `pick.rs:1-2` and the `remove_picks` doc so no intra-doc link names a deleted item; `review.rs` gets a module doc saying what Review is (a pure question sequence answered before removal).
